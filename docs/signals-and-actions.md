# Stats and actions the dash does not use yet

This lists the stats and actions the dash does not use yet, each with the CAN signal, Commander field or command that carries it, so adding one needs no new research. Sources: talas9's Model Y 2026.26.6.5 DBCs (VEH, PARTY and CH, github.com/talas9/tesla-can-signal-db), where most signal names, layouts and value tables here come from, and the "Confidence" ratings with them; the public Model 3 DBC (github.com/joshwardell/model3dbc, MIT) where a row says so; the Commander's Bluetooth protocol (github.com/niklaswa/S3XYCommander, MIT); and a capture from the test car (parked, plugged in, climate on, route set). WiFi first: anything the CAN stream carries comes from the stream; the Commander's Bluetooth is for actions, for data the stream lacks, and for what the dash shows while the stream is off (ScanMyTesla off; `Panda.fromBt`).

## How to wire one up

### WiFi CAN

1. **lib/signals.dart**: add a `Sig` to `kSignals` with the row's numbers. Its id is subscribed automatically (`kSubscribeIds`).

   ```dart
   // 0x332 BMS_bmbMinMax page 0 (selector 0|2): hottest thermistor.
   'cellTMax': Sig(0x332, 16, 8, scale: 0.5, offset: -40, mux: 0, muxLen: 2),
   ```

   The columns map one to one:
   - Bits `start|len` are the second and third arguments; `signed` is `signed: true`; `sna N` is `sna: N`. `decode()` compares the raw unsigned value before applying the sign, so the unsigned raw number is right for signed signals too.
   - Scale, offset are `scale:` and `offset:` (defaults 1 and 0); the unit is for your comment.
   - Mux `a|b = N` is `mux: N, muxStart: a, muxLen: b`. The defaults are `muxStart: 0` and `muxLen: 3`, so set `muxLen` for any selector that is not 3 bits wide, and `muxStart` for one that does not start at bit 0 (0x441's is at 48|1).
   - `Motorola` (DBC `@0`) is big-endian. `decode()` reads Intel only; those rows give the byte formula to use instead.
2. **lib/panda.dart**: add a field to `Panda` and a `case` to the `switch` in `_onFrame`:

   ```dart
   double? cellTMax; // C
   // ...
   case 'cellTMax':
     cellTMax = v;
   ```

   `decode()` has already returned null for a frame that is too short, for another mux page and for the SNA value, so the case only sees real values. Where a row warns that another bus reuses the id, guard on the length as the existing cases do (`case 'tpFL' when data.length == 7 && ...:`, `if (data.length == 8) chargePort = ...`) or on the bus (`packNewKwh` checks `bus == frames[0x352]?.bus`). Range checks for all-ones or out-of-layout values go in the case too (`cellVMax = v > 5 ? null : v;`).
3. **Teardown**: if a stale value would mislead once the link drops, clear it in `_teardown()` with the others (`navEnergyKwh = navMinutes = speedLimit = null;`).
4. **test/obd_test.dart**: decode a payload as the existing expects do, ideally one from a capture. For logic in `Panda`, feed frames with `p.onFrame(id, bus, bytes)` and check the field.

   ```dart
   // 0x332 page 0, byte 2 = 0x60: 96 * 0.5 - 40 = 8.0 C.
   expect(decode(kSignals['cellTMax']!, [0x00, 0, 0x60, 0, 0, 0]), 8.0);
   ```

5. Show it from the `Panda` instance (`_obd` in main.dart), which notifies its listeners at about 30 Hz.

Multi-page frames (BMS_log2, DIR_debug, VCRIGHT_logging1Hz, VCFRONT_logging1Hz, BMS_brickMeasurements) add stream traffic for a page that refreshes only every few seconds to about a minute; keep the last value.

### Commander data (Bluetooth)

1. **lib/commander.dart**, in `Commander._open()`: add the field number to the subscription, for example `subscribeRequest(const [6, 7, 8, 9, 101, 49, ...Panda.btFields])`. The first push after a subscribe carries the current values and later pushes only changes, and every field is optional, so keep the last value. A value WiFi also has, shown from Bluetooth while WiFi is off, goes in `Panda.btFields` and `Panda._applyBt` instead (lib/panda.dart), which keep the last values for you.
2. Add a field to `Commander` and read it in `onPush`. There `d` holds the PushVehicleDataHolder's fields by number (the same number as the field in the row), as `_fields()` decodes them: varints as `int`, length-delimited as `List<int>`, fixed32 as `double`.

   | Type in the row | Read it as |
   |---|---|
   | float (fixed32) | `if (d[n] case final double v) x = v;` |
   | string | `if (d[n] case final List<int> s) x = utf8.decode(s, allowMalformed: true);` |
   | uint32, enum, bool | `if (d[n] case final int v) x = v;` (bool: `v != 0`) |
   | int32 | as uint32; a negative value is a 10-byte varint, which `_fields()` reads back as a negative `int` |
   | sint32, sint64 (zigzag) | `if (d[n] case final int v) x = (v >>> 1) ^ -(v & 1);` |

   Then multiply by the row's "x" scale. Those scales usually equal the DBC scale of the matching CAN signal (the DC charge current is an exception, see its row), and there is no offset, so temperatures arrive signed with the offset already applied. Fields 88 and 93-104 set bit 7 (0x80) when the value came from an S3XY press: mask it off with `& 0x7F`, as widgets.dart does with `recircMode`.
3. Clear the field in `_teardown()`, next to `navDest`.
4. **test/commander_test.dart**: feed a hand-built push as the test 'trip figures from vehicle-data pushes' does. A push is `08 10` (push type 16), `ca 01` (field 25) and a length, then the holder's fields; `c.onPush(hex('0810ca0103a80601'))` sets field 101 to 1.

Fields 1-23 come through the Commander's own link to the car (`Commander.carLink`, shown in the Diagnostics log), which it drops while ScanMyTesla is on: expect them with ScanMyTesla off, when fields 6-9 (the route) arrive. The scroll-wheel events use another request, which commander.dart does not build yet; their rows give the bytes.

### Commander action (Bluetooth)

1. **lib/commander.dart**: add an entry to `enum S3xyAction`, `name(id, state, 'Label')`, with the row's Id and one of its States:

   ```dart
   rearFog(51, 0, 'Rear fog'), // TeslaAction.rearFogLights: toggle
   ```

   `tryActionRequest()` always sends switch type 1, so nothing else changes. `_varint()` encodes only non-negative ints: a negative state (track mode stability) must be given as its uint32 value, `n & 0xFFFFFFFF`.
2. If it opens a closure, add its id to the `opens` getter (those act only in P).
3. Press it with `Commander.tryAction(...)`: a chip in `_Actions` in widgets.dart (its taps go to `_press`, which checks gear and link), or a car panel button, `_btn(S3xyAction.x, Icons.y)`, in car_panel.dart.
4. **test/commander_test.dart**: check the bytes. For an id and a state below 128 they are `081cba02090a0708` + id + `10011a01` + state, in hex; fold mirrors (7, 0) is `081cba02090a07080710011a0100`.

Some actions need the Commander added as a key to the car; their notes say so (`Commander.carLink` shows that pairing). Confidence is "untested on this car" unless a row says otherwise.

### Reading the tables

- One section per area, with a table per route: WiFi CAN, Commander data, Commander actions. A stat that is on both WiFi and Bluetooth is listed under WiFi, with its Commander field in the notes.
- Frame: the id, the DBC message, the DBC that defines it (VEH = vehicle bus, PARTY = party bus, CH = chassis bus, public M3 = the public Model 3 DBC), and its length and cycle where known.
- Bits: `start|len` as the DBC counts it (Intel unless it says Motorola), then `signed` and the raw SNA value, if any.
- On car: seen = the id is on the test car's captured WiFi stream (with its bus tag and rate where known); not seen = absent from that parked capture, which does not rule it out while driving or charging. The Commander tags nearly every frame as bus 0 (0x132 shows as bus 1), so filter by bus only where a row says so.
- Rows that say "Do not use" decode to wrong values on this car and need a capture first.
- Not in any source: a glovebox-open state (the DBCs have only UI_gloveboxRequest), a puddle-lamp on/off, and a general chime or volume signal on CAN. Left out on purpose: alert matrices, counters, checksums, UDS and calibration internals, and features this car does not have (sunroof, tonneau, V2X/Powershare, inlet heater).
- Left out because the dash already has them: every signal in lib/signals.dart, Commander fields 6, 7, 8, 9, 101 and those in `Panda.btFields`, and every `S3xyAction`.
